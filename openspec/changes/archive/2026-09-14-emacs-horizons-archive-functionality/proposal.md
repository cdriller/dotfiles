## Why

Six GTD "horizon type" directories under `~/notes/horizons/` (Project, Area, Life, Goal, Vision, Actions) grow without bound today: completed projects, no-longer-relevant areas, and finished actions stay mixed in with active ones forever. This clutters the `C-c n` picker's candidate lists, `org-refile-targets`, and (for Actions) the active context files themselves, with items that no longer need day-to-day attention. The recent `emacs-refactor-horizon-setup` change consolidated all six types onto one shared `prilepp/define-horizon-type` macro plus a registry (`prilepp/horizon-types`) specifically so that an archive mechanism could be added once, generically, instead of once per type. This change adds that mechanism.

## What Changes

- New generic path-mirroring: any path under `~/notes/` maps to the same relative path under `~/notes/archive/` (e.g. `~/notes/horizons/proj/X.org` -> `~/notes/archive/horizons/proj/X.org`).
- New command `prilepp/archive-entry`: prompts for a horizon type (from the registry), then an existing entry name in that type, and moves that entry's `.org` file to its mirrored archive path (creating archive directories as needed).
- New command `prilepp/restore-entry`: prompts for a horizon type, then an existing *archived* entry name, and moves it back to its mirrored active path.
- Both commands trigger `org-id-update-id-locations` afterward (scoped to old+new path) so `id:` links into headings inside the moved file keep resolving.
- Fix for a pre-existing stale-link bug (present since before this change, in every `*-ensure-file` function generated by `prilepp/define-horizon-type`): following a link to an entry that has been archived currently silently creates a new empty active file with the same name, instead of finding the archived one. This change makes every `*-ensure-file` function check the mirrored archive path first (via advice added generically over every function registered in `prilepp/horizon-types`) and open the archived file if found there, before falling back to today's "create a new active file" behavior.
- `C-c n` (`prilepp/find-entity`) picker: for each of the six horizon-type sources (Action, Project, Area, Goal, Vision, Life), archived entries now also appear as candidates, always ordered after that type's active entries (lowest priority within the same narrow key/source) - not as a separate mode or narrow key. Selecting an archived candidate opens the archived file directly (does not recreate an active one).
- Heading-level archiving: for every horizon-type file, `org-archive-location` is set (buffer-locally, via a hook keyed off the registry) so that Org's built-in `C-c C-x C-a` (`org-archive-subtree`) archives a heading into the mirrored file under `~/notes/archive/...` instead of the Org default (same-directory `_archive` file). No new command - this reuses Org's existing archiving command and keybinding, only redirecting its destination.
- Manual triggers only: no automatic archiving on `DONE`/state change for either whole files or individual headings (per explicit decision - see design.md).
- Scope: archiving (file-level, heading-level, and the picker's low-priority search behavior) applies to exactly the six horizon types tracked in `prilepp/horizon-types` (Action, Project, Area, Goal, Vision, Life) - not Zettel, Literature, Person, Routine, Someday, Agenda, or Heading sources in the picker, which have no archive concept.

## Capabilities

### New Capabilities
- `emacs-horizon-archive`: Generic archive/restore mechanics for all six horizon types - the path-mirroring rule, `prilepp/archive-entry`/`prilepp/restore-entry` commands, the stale-link fix in `*-ensure-file`, the `org-id-update-id-locations` refresh after moving a file, and the per-buffer `org-archive-location` mapping that redirects `org-archive-subtree` to the mirrored archive file.

### Modified Capabilities
- `emacs-keybindings`: The existing "Unified node picker" requirement (`C-c n`) is extended - for the six horizon-type sources, archived entries now also appear as low-priority candidates alongside (after) active ones, and selecting one opens the archived file rather than recreating an active one. All other node types and all previously-specified RET/`C-i`/`C-c` semantics are unchanged.

## Impact

- Affected files: `emacs/.config/emacs/lisp/init-horizon-types.el` (registry addition to the macro), a new `emacs/.config/emacs/lisp/init-horizon-archive.el` (path-mirroring, archive/restore commands, stale-link-fix advice, `org-archive-location` hook), `emacs/.config/emacs/lisp/init-find-entity.el` (extend the six horizon-type sources' `:items` with low-priority archived candidates), `emacs/.config/emacs/init.el` (new `require`, ordered after `init-projects`/`init-files` so the registry is populated first).
- Not affected: `init-org.el`'s `org-refile-targets` (already scoped to `~/notes/horizons/`, so it naturally excludes `~/notes/archive/`), which-key labels for existing bindings, the five non-horizon `C-c n` sources (Zettel, Literature, Person, Routine, Someday, Agenda, Heading).
- User-facing: two new interactive commands (not yet bound to a key - see design.md for the proposed binding), `C-c n` candidate lists grow to include archived entries, `C-c C-x C-a` inside any horizon-type file now archives into `~/notes/archive/...` instead of Org's default same-directory `_archive` file.
- No new packages; reuses Org's built-in `org-archive-subtree`/`org-archive-location` and `org-id-update-id-locations`.
- Depends on `emacs-refactor-horizon-setup` (must be applied first - it is, per the current repo state).
