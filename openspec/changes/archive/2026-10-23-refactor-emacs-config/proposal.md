## Why

The GTD "horizon type" boilerplate (Action, Project, Area, Goal, Vision, Life) is generated by one macro (`prilepp/define-horizon-type` in `init-horizon-types.el`), but the six concrete declarations that use it are split across two files with names that no longer describe their contents (`init-projects.el` holds five of the six plus unrelated Routine code; `init-files.el` holds the sixth plus unrelated quick-open commands). `agendas`, a seventh directory-of-one-file-per-entry list that behaves identically to the six, was never converted to the macro and instead hand-duplicates the exact boilerplate (`prilepp/agendas--list-entries`, `prilepp/agendas-ensure-file`, `prilepp/agendas-find`) the macro exists to eliminate — so it also misses out on archive/restore and title-based display, which every macro-defined type gets for free via the `prilepp/horizon-types` registry. Separately, `prilepp/slugify`, a generic string utility, lives in the contacts module (`init-contacts.el`) but is used by the Routines code in `init-projects.el`, an implicit cross-file dependency with no `require` declaring it.

Converting `agendas` to the macro means it joins the `prilepp/horizon-types` registry like every other type, which is what actually drives archiving and title display — so this also extends those capabilities to Agenda. Since "horizon of focus" (GTD's altitude model: Runway/Projects/Areas/Goals/Vision/Purpose) doesn't conceptually include a list of meeting/person agendas, this change also renames the type-family concept from "horizon type" to "GTD list type" throughout the code, so the vocabulary matches what it actually covers.

## What Changes

- Merge all seven GTD list-type declarations (Action, Project, Area, Goal, Vision, Life, Agenda) into a single new file, replacing their current split across `init-projects.el` and `init-files.el`.
- Convert `agendas` from its hand-written list/ensure/find functions to a `prilepp/define-gtd-list-type` (renamed macro) declaration, removing the duplicated boilerplate. **Behavior change**: Agenda entries become archivable/restorable via the existing archive commands, gain the "(archiviert)" annotation and archived-entries-sorted-last behavior in the `C-c n` picker, and are shown by their file's `#+title:` instead of filename everywhere other list types already are — exactly the same behavior the six existing types already have, now extended to a seventh.
- Rename the "horizon type" concept to "GTD list type" throughout the Elisp code: the macro (`prilepp/define-horizon-type` → `prilepp/define-gtd-list-type`), the registry (`prilepp/horizon-types` → `prilepp/gtd-list-types`) and every generic helper built on it (entry listing, title lookup/caching, label de-duplication, archive path mirroring, archive/restore commands, the ensure-fn archive fallback advice, the `org-archive-location` redirect). File names carrying "horizon" in them are renamed to match. On-disk note directories (e.g. `~/notes/horizons/proj/`) and the OpenSpec capability paths (`emacs-horizon-archive`, `emacs-horizon-titles`) are left as-is — this is a code/terminology rename, not a data migration or a spec reorganization.
- After the list-type declarations move out of `init-projects.el`, only Routine code remains there; rename the file to reflect that.
- Extract `prilepp/slugify` (and any other function used across more than one domain module) into a new `init-utils.el`, and add an explicit `require` for it wherever it's used, replacing the current implicit load-order dependency.
- No changes to keybindings, directory layout, file formats, or the behavior of the six existing list types beyond what's listed above.

## Capabilities

### New Capabilities
(none — Agenda gains behavior that the existing horizon-type/GTD-list-type capabilities already define generically; no new capability is introduced)

### Modified Capabilities
- `emacs-horizon-archive`: extends archiving/restoring, the archived-file-resolution fallback, and the subtree-archive redirect from six list types to seven, adding Agenda.
- `emacs-horizon-titles`: extends title-based (rather than filename-based) display from six list types to seven, adding Agenda, across every picker/command the existing requirement already enumerates.
- `emacs-keybindings`: updates the `C-c n` picker requirement's enumeration of "the six node types that support archiving" to include Agenda as a seventh, with archived Agenda entries appearing (and sorted) exactly as for the other six.

## Impact

- **Code**: `emacs/.config/emacs/lisp/init-horizon-types.el`, `init-horizon-archive.el`, `init-projects.el`, `init-files.el`, `init-contacts.el`, `init-find-entity.el`, `init-org.el`, `init.el` (require list/order), plus new files for the merged list-type declarations and for `init-utils.el`.
- **User-visible**: Agenda entries can now be archived/restored (`C-c a a` / `C-c a r`) and are shown by title instead of filename in the `C-c n` picker and elsewhere; everything else (keybindings, commands, directory structure) is unchanged.
- **No changes** to `~/notes/` directory structure, to any existing `.org` file, or to the six existing list types' observable behavior.
